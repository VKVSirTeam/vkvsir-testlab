VKV Sir Test Lab: renovation audit

A complete pass over test.vkvsir.com and www.vkvsir.com: all 19 public screens measured with the same checks at laptop (1366 px) and phone (375 px) width, light and dark mode, plus the code of every signed-in screen (practice, test, results, dashboard, profile). Each finding names where it is, what we saw, and what to do.

11–18font sizes per screen (target: 8 across the app)
192!important overrides in app.css
102fixed colours that bypass the theme
105unlabelled controls on one exam page
111 pxheader height on a phone (14% of the screen)

Verdict. The engine is strong: about 75,000 questions, a clean exam browser with branch filters, honest timing, anti-cheat, translations, job prep and a resume builder. What holds the app back is the layer students touch: one long home page doing every job, the same idea under three names, layouts that break on phones in specific places, a header that eats the screen, and a visual style that drifts from page to page. None of this needs the content to change. It needs a design system, a clear map of places, and careful screen-by-screen rebuilding, done in stages so the site never goes down.

Decisions taken

  • Hosting stays on GitHub Pages. Deploys are unlimited, which suits frequent updates. The 404-status problem is solved inside GitHub Pages instead (see Search & sharing).
  • Names: “Practice” and “Test”. Used everywhere: menus, buttons, tags, results, leaderboard. “Quiz”, “Test yourself” and “self assessment” are retired.
  • Leaderboard shows full name and college.
  • Leaked-password protection is on.

Already fixed (Phase 0, live)

  • One pop-up at a time on a first visit (sign-in box, tour and tip card no longer stack); the tour is a solid bottom card on phones.
  • No more invisible sections while scrolling; the footer waits for content.
  • Deep links (/exams, /t/…, /p/…) now load the current page, fonts and code (they were loading a months-old copy).
  • Maths in the drill (745); 44 px phone tap targets for menu, footer and social links.
  • Database: a view running with owner rights fixed, admin functions closed to anonymous visitors, internal helpers closed, fixed search path on 34 functions.

Corrections to v1 of this report. The resume builder code already loads only when opened, and all files are already compressed (app.js is 104 KB over the network, not 353 KB). The performance section below is updated accordingly.

Structure & menus

CRITICALOne page does every job

The home page (12 screens long, ~9,000 elements) contains the pitch, the subject picker with 1,330 checkboxes, ready-made tests, job prep and resume teasers, FAQs and the leaderboard. Top menu items scroll within it.

Give each job its own place with its own URL. The home page only introduces them.

CRITICALThe good structure exists, but students never reach it

The exam browser (/exams?k=university) already groups by family and has a branch filter (Mechanical, Civil, Electrical, ECE, CS & IT, Instrumentation). The home “Fundamentals” list ignores it and shows Automobile, CAD, Civil, CS, Current Affairs… in one A–Z list.

Make the exam/branch browser the main way in. Retire the flat list.

HIGHExams has no menu item

The top menu is Practice & Tests · Job Prep · Resume Builder (+ Dashboard when signed in). Exams is reachable only through home-page cards, and on /exams the highlighted item is “Practice & Tests”.

HIGHDuplicate entry points

“Explore by your goal” (3 cards) and “Choose what to practise” (3 tracks) repeat each other; tests appear under Practice, Ready-made tests and Exams; four different buttons (“Start practising”, “Choose a subject”, “Practise my subjects”, “Find your exam”) lead to nearly the same place.

Proposed map

Laptop: top bar Phone: bottom tab bar (5) ├── Home / introduce + continue where you left off ├── Practice /practice Engineering ▸ Branch ▸ Subject ▸ Unit ▸ Topic │ General (GK · Current affairs · Science · English · Reasoning · Aptitude) │ Software & programming · Aptitude drill ├── Test /test Topic/unit tests · Full mock tests · Daily test · Group test link ├── Exams /exams Family ▸ Exam ▸ Branch ▸ Section map (existing page, promoted) ├── Career /career Job Prep · Resume builder └── Me /me Progress · History · Weak topics · Saved · Leaderboard · Settings Utility (top-right): search · language · theme · sign-in/avatar
  • Remember the student's stream and branch (asked once in a two-tap chooser, changeable in Me). Every list opens that cluster first.
  • Clusters everywhere, collapsible, each with counts (“Mechanical · 14 subjects · 21,400 questions”).
  • Search across subjects, topics, exams and companies, opened with / on a laptop.
  • “Continue” card on Home and Me: the last unfinished practice or test.

Navigation & back

CRITICALMenu drawer unreachable on phones

At 375 px the menu button is hidden (display:none), so the drawer with Profile, “Why Test Lab” and the vkvsir.com link cannot be opened.

HIGHNo breadcrumbs or “up” on deep pages

Only the exam page has “← All exams”. Subject, unit, test and result pages give no path back except the browser button.

Breadcrumbs on every inner page (Practice › Mechanical › Thermodynamics › Unit 3), shortened to “‹ Thermodynamics” on phones.

HIGHScroll position lost on Back

The router never restores scroll; returning from a subject to a long list starts at the top again.

Store scroll per history entry and restore it on popstate.

MEDIUMSection links don't change the URL

Home tabs and “Explore ↓” links scroll without updating the address, so Back leaves the site section instead of returning.

MEDIUMFocus not moved on page change

After navigation, keyboard and screen-reader focus stays on the old link. Move focus to the new page heading.

One sentence plus details behind “How it works”.

Motion & feedback

HIGHA spinner is the only loading state

Skeletons shaped like the real content (cards, question, options) and a thin top progress bar for waits over 300 ms.

HIGHNo page transition

A 180 ms fade-and-rise between pages (View Transitions API where supported). The header and bottom bar stay still.

MEDIUMAnswer feedback is static

Practice: correct option fills green with a check; a wrong pick shakes gently and turns red; the explanation slides open. Test: the chosen option fills and Next pulses once.

MEDIUMResults arrive all at once

Score ring counts up once; topic bars grow in sequence; confetti only for a personal best or a rank gain.

LOWMicro-interactions

Cluster chevrons rotate, checkboxes tick with a short draw, copy/share shows a toast, the timer ring turns amber at 10 s.

Rules: nothing over 300 ms, nothing blocks input, everything off under “reduce motion”.

Staged plan

Each stage ships on its own, keeps every link working, and is checked on a laptop and a phone (light and dark) before it goes live. Laptop and phone are done together, not one after the other.

Stage 1 · Quick wins (2–3 days)

Phone menu drawer reachable; timer and duration pickers without broken words; “Practice”/“Test” tags corrected everywhere; repeated titles removed; per-page titles; heading spacing; 404 page with search and doors; focus ring; labels on exam-page controls; leaderboard returns full name and college.

Stage 2 · Foundation (about 1 week)

Design tokens (type, colour, spacing, radius, shadow), Lucide icons replacing emoji, Light/Dark/System switch, component set (buttons, chips, cards, inputs, tabs, sheets, toasts, skeletons), CSS rebuilt on tokens, real 200 pages for every public route, sitemap, CSP meta.

Stage 3 · App shell and places (about 1 week)

56 px header and phone bottom bar; pages for Practice, Test, Exams, Career, Me; breadcrumbs; scroll restore; page transitions; branch chooser remembered; search; Continue card.

Stage 4 · Core screens (1–2 weeks)

New Home; Practice browser with clusters and sticky selection tray; subject and test start pages in two columns; exam simulation mode with palette; practice explanation panel; results report; leaderboard page with podium and own rank; Me dashboard.

Stage 5 · Career and tools (1 week)

Job Prep in steps with plan tabs; resume builder re-laid; drill with score and streak; shared-question landing; teacher class view.

Stage 6 · Polish and growth (ongoing)

Micro-animations, installable app with offline papers, share cards, daily test, college leaderboard, main-site tiles and menu, admin inbox, automated journey tests.
