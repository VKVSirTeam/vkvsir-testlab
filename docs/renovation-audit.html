VKV Sir Test Lab: renovation audit

A full review of test.vkvsir.com and www.vkvsir.com on desktop (1366 px) and phone (375 px). It covers the structure, every main page, the look, motion, speed, code and security, and ends with one phased plan that fits it all together.

Verdict. The content and features are strong; the shell around them is not. The site reads as one very long page that keeps adding sections, instead of an app with clear places. Practice, Quiz, Exams, Job Prep and Resume all live inside the home page, so the same things show up two or three times. Fonts, sizes, corners and icons vary from section to section. Fixing this is mostly restructuring and a design system, not new features. The plan below keeps every feature, the URLs, the question bank and the data.

The five decisions that matter most

  1. Split the app into five clear places: Home, Practice, Quiz & Tests, Exams, Career (Job Prep + Resume), plus My Progress. Each has its own page; the home page only shows them.
  2. Browse in clusters, not lists: stream → branch → subject → unit → topic, collapsible at each level, with a branch/stream chooser remembered per user.
  3. Make Practice and Quiz visibly different: different colours, icons, page layouts and names everywhere: “Practice” (learn, no pressure) and “Quiz” (timed, scored, ranked).
  4. One design system: one font pair, an 8-step type scale, 3 corner sizes, one icon set (no emoji), light and dark themes, and shared components.
  5. An app shell: fixed top bar on desktop, a bottom tab bar on mobile, breadcrumbs, a working Back button, page-transition and skeleton loaders, and real 200 responses for every page.

Critical issues (fix first)

CRITICALEvery inner page returns HTTP 404

Seen: /exams, /t/mock-qa, /drill, /p/… are served from 404.html by GitHub Pages, so the status is 404 even though the page then renders.

Fix: Google will not index these pages and WhatsApp/LinkedIn previews may fail. Move hosting to Cloudflare Pages or Netlify (free) with an SPA rewrite rule (/* → /index.html 200), which also lets us set security headers. Keep the same domain and URLs.

CRITICALMobile welcome tour is see-through and covers content

Seen: on a 375 px phone the “Step 1 of 5” tour box is translucent and sits on the stats, so both texts are unreadable; “Next” is faint.

Fix: solid card with shadow, dim the page behind it, anchor it to the bottom on phones, and show it only once after the first visit (not on landing).

CRITICALContent appears late or as grey blocks

Seen: the first paint shows a spinner with the footer already in place (the page jumps when content arrives). While scrolling, whole sections are empty grey areas until they fade in.

Fix: skeleton placeholders the same size as the real content, the footer rendered only after the main content, and scroll-reveal that starts from a visible state (never opacity 0).

CRITICALDatabase: one “security definer” view and public-callable admin-level functions

Seen (Supabase security advisor): 1 ERROR (security-definer view), several SECURITY DEFINER functions callable by anonymous users, 34 functions with an unfixed search path, and leaked-password protection turned off.

Fix: review each function, revoke anonymous execute where it is not needed, set search_path on all, switch the view to security-invoker, and turn on leaked-password protection in Auth settings.

Structure & navigation

What is wrong today

HIGHEverything lives on the home page

The practice picker (1,330 checkboxes), exam explorer, ready-made tests, job prep and resume teasers all sit inside one 9,744 px page. The top menu (“Practice & Tests”, “Job Prep”, “Resume Builder”) mostly scrolls to anchors on that same page, so the URL and Back button don't match what the student sees.

HIGHFlat subject lists

Opening “Fundamentals” shows Automobile, CAD, Civil Core, CS Fundamentals, Current Affairs, Electrical Core… in one A–Z list. A CS student has to scroll past every Mechanical subject. Exams already group by branch; subjects do not.

HIGHThe same thing in several places

“Explore by your goal” (3 cards) and “Choose what to practise” (3 tracks) say the same thing twice; tests show up under Practice, under “Ready-made tests” and in Exams; “Start practising”, “Choose a subject”, “Practise my subjects” and “Find your exam” all lead to nearly the same spot.

MEDIUMMixed labels

A placement mock is tagged “Practice”; the track names are Fundamentals / University syllabus / Semester for the same idea; “self assessment” wording. Pick one name per idea and use it everywhere.

Rules for the new structure

  • Clusters with expand/collapse at every level, an item count on each heading (“Mechanical · 14 subjects · 21,400 Q”), and a search box at the top that filters as you type.
  • Remember the student's stream and branch (asked once, changeable from “Me”), open that cluster first, and keep the others collapsed.
  • Breadcrumbs on every inner page (Practice › Mechanical › Thermodynamics › Unit 3), and the browser Back button always goes one level up.
  • One primary action per screen. Secondary actions are text or ghost buttons.
  • A sticky selection tray at the bottom while choosing topics (“3 topics · 30 Q · Start”), instead of a button far below the list.

Home page

HIGHHero

Today: an orange eyebrow “Free for every student · Practice · Job prep · Resume” (wraps to two lines on mobile), a four-line paragraph, then three stacked buttons of equal weight.

New: one short headline (e.g. “Practise. Test. Get placed.”), one line of support text, two buttons (Start practice · Take a quiz), a live counter strip (questions, subjects, exams), and a real product preview on the right (an animated question card) instead of a feature grid. Drop the eyebrow on mobile.

HIGHBelow the hero: four doors, then proof

Replace the 20+ sections with: 4 door cards (Practice · Quiz & Tests · Exams · Career), each with its own colour and icon → “Today's quiz” card → leaderboard peek (top 5 this week) → exam logos/family strip → company strip (keep the marquee, slower, pause on hover) → short “How it works” in 3 steps → footer. “20+ subjects”, “40+ roles” undersell a bank of about 75,000 questions. Show real numbers from the database (questions, subjects, exams, attempts this week), refreshed by the existing catalog cache.

MEDIUMFooter

Two different footers exist (home vs inner pages). Use one footer with 4 columns (Practice · Quiz · Career · About), social icons in one row, and the disclaimer as one short line linking to the full text.

Write these as CSS tokens in one place (app.css :root), then refactor components to use only tokens. That single change removes most of the “looks different everywhere” feeling.

Motion & loading

  • Page change: a 180 ms fade-and-slide between pages (the View Transitions API in Chrome, fade elsewhere); the header stays still.
  • Loading: skeleton cards in the real layout instead of a centre spinner; a thin progress bar at the top for anything over 300 ms.
  • Answering: a soft green pulse and check on a correct answer, a gentle shake and red outline on a wrong one; the explanation slides open.
  • Results: the score ring counts up once; confetti only for a personal best or rank change.
  • Lists: clusters expand with a height animation; chevrons rotate.
  • Rules: nothing over 300 ms, nothing that blocks input, and everything off when the phone has “reduce motion” on.

Mobile

HIGHBottom tab bar

On phones, replace the top pill row with a 5-item bottom bar (Home · Practice · Quiz · Exams · Me), within thumb reach, with the active tab highlighted. The top bar keeps only the logo, search and sign-in/avatar.

HIGHTap targets

20 links and buttons are under 36 px tall. Make every tap target at least 44 × 44 px, with 8 px between them.

MEDIUMQuestion screen on a phone

Options as full-width cards, the timer and progress in a slim sticky top bar, Next/Previous in a sticky bottom bar, images tap-to-zoom (already present) with pinch.

MEDIUMInstallable app

A manifest exists but there is no service worker. Add one so the site installs like an app (home-screen icon, splash screen) and opens instantly, with recently used papers cached for weak networks.

Leaderboard & profile

  • Leaderboard page: podium for the top 3 (avatar, name, score), then a clean ranked list; filters for this week / this month / all time and by subject or exam; the student's own row pinned at the bottom (“You · #148 · ↑12”).
  • Home peek: top 5 this week with a “See full leaderboard” link.
  • Me page: streak, total questions, accuracy ring, strong and weak topics as bars, recent attempts, saved questions, language and theme settings.
  • Fairness: rank only quiz mode, minimum questions per period, and hide names by default (initials + city) to respect privacy.

www.vkvsir.com (main site)

The main site is personal and course-led, which is right, but the Test Lab gets one small “Take a free test” button.

  • Hero: three equal entry tiles under the intro: Courses · Practice subjects · Take a quiz. Replace “self assessment” wording with “Quiz” or “Test” everywhere.
  • Top menu: Home · About · Courses · Test Lab ▾ (Practice, Quiz, Exams, Career) · Media · Blog · Join.
  • The Test Lab section shows the live question count (74,593), three cards, and a “Try a 5-question quiz” embed-style teaser.
  • Match colours and fonts between the two sites so moving from one to the other feels like one product.

Speed & code

HIGHOne large script

app.js is 353 KB (946 functions) plus resume.js 110 KB and app.css 119 KB, all unminified and loaded on every page. Split by page (home, practice, quiz, exams, career, admin), minify with a small build step (esbuild/Vite), and load the resume and admin code only when opened. Expect the first load to drop to about a quarter.

HIGH1,330 checkboxes built up front

Render a cluster's contents only when it is opened, and build the topic tree from the cached catalog. This also removes the long-page scroll lag on older phones.

MEDIUMConsole errors

Each page logs several 401/404 resource errors. Clean these up; they hide real problems and slow loading.

MEDIUMRouter

Use a single client router: each place has its own URL, page titles change per page, scroll position is restored on Back, and an unknown URL shows a friendly “Page not found” with links.

Security

  • Security headers (after moving hosting): Content-Security-Policy, HSTS, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, frame-ancestors.
  • XSS: 100 places write raw HTML (innerHTML). Route every user- or database-sourced text through one escape helper, and allow HTML only for trusted question content after sanitising (DOMPurify).
  • Database: fix the advisor findings listed under Critical; add a monthly check.
  • Auth: turn on leaked-password protection, rate-limit report and translation endpoints, keep service keys server-side only (already true).
  • Admin: admin pages behind role checks on the server (RLS), not only hidden in the UI.

Accessibility

  • 5 images without alt text on the home page; every question image needs a short alt (“Figure 3: milling cutter”).
  • Visible focus ring on all controls; the full quiz usable by keyboard.
  • Contrast: pale grey text on pastel tiles fails WCAG AA in places; use the muted token only on plain backgrounds.
  • Timers announced to screen readers at 1 minute and 10 seconds left, not every second.
  • Language selector and translations marked with the right lang attribute so phones read Hindi correctly.

Rollout plan

Each phase ships on its own, keeps all URLs working, and is checked on a laptop and a phone before going live.

Phase 0 · Quick fixes (1–2 days)

Fix the mobile tour overlay, scroll-reveal grey blocks, footer jump and drill maths; unify the footer; enlarge tap targets; fix the database advisor items and turn on leaked-password protection.

Phase 1 · Foundation (about 1 week)

Design tokens (type, colour, spacing, radius), the icon set replacing emoji, light/dark themes, the button/card/chip components, a move to Cloudflare Pages with SPA rewrite and security headers, and a build step with code splitting.

Phase 2 · App shell and structure (about 1 week)

Router with real pages (Home, Practice, Quiz, Exams, Career, Me), desktop top bar and mobile bottom bar, breadcrumbs, page transitions, skeleton loaders, and the clustered stream → branch → subject browser with search and the remembered branch.

Phase 3 · Core screens (about 1 week)

New home page, separate Practice and Quiz screens with their own look, the exam-grade quiz with palette and results page, the leaderboard page and peek, and the Me page.

Phase 4 · Polish and growth (ongoing)

Micro-animations, installable app with offline cache, daily quiz, the main-site update with three entry tiles and the Test Lab menu, sharing previews per page, and accessibility pass.

Decisions the owner should confirm before Phase 1: moving hosting from GitHub Pages to Cloudflare Pages (free, same domain); the final names (“Practice” and “Quiz”, or “Practice” and “Test”); and whether leaderboard names show in full or as initials.
